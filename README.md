# 🎓 بوت مراقب LMS - Telegram Bot

> بوت تلجرام يفحص مواد Moodle دورياً ويرسل تنبيهات عند اكتشاف واجبات أو كويزات أو موارد جديدة. يعتمد وقت وصول التنبيه على فترة الفحص المختارة.

---

## 🚀 خطوات التشغيل

### الخطوة 1: إنشاء بوت تلجرام

1. افتح تلجرام وابحث عن **@BotFather**
2. أرسل `/newbot`
3. اختر اسماً للبوت (مثال: `LMS Monitor`)
4. اختر username للبوت (مثال: `mutah_lms_bot`)
5. ستحصل على **Token** - احفظه

### الخطوة 2: إعداد متغيرات البيئة في ملف `.env`

انسخ `.env.example` إلى `.env` واضبط القيم المطلوبة (كل من `OWNER_TELEGRAM_ID` و`ENCRYPTION_KEY` إلزاميان عند التشغيل):

```env
TELEGRAM_BOT_TOKEN=1234567890:ABCdefGHIjklMNOpqrSTUvwxYZ
OWNER_TELEGRAM_ID=123456789
ENCRYPTION_KEY=<مفتاح Fernet مولّد بالأمر أدناه>
```

لتوليد مفتاح `ENCRYPTION_KEY` صالح:

```powershell
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

### الخطوة 3: تثبيت المتطلبات

```powershell
pip install -r requirements.txt
```

### الخطوة 4: تشغيل البوت

```powershell
python bot.py
```

## 📱 كيفية الاستخدام

بعد تشغيل البوت، افتح تلجرام وابدأ المحادثة:

| الأمر | الوظيفة |
| `/start` | تشغيل البوت وفتح لوحة التحكم الرئيسية بالأزرار |
| `📱 لوحة التحكم` | زر القائمة السفلي وداخل الشات لفتح تطبيق Telegram Mini App التفاعلي |
| الأزرار | استيراد المواد تلقائياً بنقرة واحدة، إدارة المواد، تشغيل/إيقاف المراقبة، الفحص اليدوي، الإعدادات والإحصائيات |

أثناء تشغيل المراقبة، يرسل البوت طلباً خفيفاً لنظام الجامعة كل دقيقتين للمحافظة على الجلسة نشطة. إذا انتهت الجلسة، يوقف الفحص ويرسل تنبيهاً مع زر إعادة تسجيل الدخول؛ تبقى المواد وإعدادات المراقبة محفوظة، ويستأنف البوت المتابعة بعد نجاح الدخول.

## 🔔 أنواع الإشعارات والمميزات الذكية

- **📚 واجب جديد وتتبع حالة التسليم:** يرصد البوت الواجبات ومواعيدها بدقة. إذا قام الطالب بحل وتسليم الواجب في LMS، يكتشف البوت ذلك فوراً ويتوقف عن إرسال تنبيهات الموعد المتبقي (24 ساعة / 3 ساعات / ساعة واحدة) لتجنب الإزعاج.
- **📝 كويز جديد:** مع الموعد ورابط الكويز وحالته.
- **📎 إرسال الملفات والمستندات مباشرة:** عند نزول سلايدات أو ملفات PDF أو ملخصات جديدة، يقوم البوت بتحميلها وإرسالها مباشرة كـ مستندات Telegram Document داخل المحادثة.
- **⚡ نظام الفحص المشترك (Shared Course Scraping):** عند اشتراك عدة طلاب في نفس المادة، يفحص البوت المادة مرة واحدة في الدورة ويشارك المحتوى في الذاكرة المؤقتة (Cache)، مما يقلل عدد الطلبات على خوادم الجامعة بنسبة 90% ويحمي من حظر الـ IP.

## 🛡️ الأمان

- **تشفير كلمات المرور (Fernet — AES-128-CBC + HMAC-SHA256):** تُشفر كلمات المرور باستخدام مكتبة `cryptography.fernet` (تشفير متماثل `AES-128-CBC` مع توثيق `HMAC-SHA256`) وبصيغة مسبوقة بالبادئة `enc:v1:` قبل تخزينها في قاعدة البيانات (SQLite أو PostgreSQL).
- **مفتاح التشفير الإلزامي (`ENCRYPTION_KEY`):** يُقرأ المفتاح حصرياً من متغير البيئة `ENCRYPTION_KEY` بنظام Fail-Closed (يتوقف التشغيل برسالة خطأ واضحة إذا كان المفتاح مفقوداً أو غير صالح، ولا يعود أبداً للنص الصريح). لتوليد مفتاح جديد:
  ```powershell
  python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
  ```
- **ترحيل كلمات المرور القديمة وتدوير توكن البوت:** عند التشغيل تستدعي `init_db()` ترحيلاً تلقائياً متكرر الأمان (idempotent) يحوّل كلمات المرور القديمة المشفّرة سابقاً بمفتاح مشتق من `TELEGRAM_BOT_TOKEN` أو المخزّنة كنص صريح إلى الصيغة الجديدة `enc:v1:` باستخدام `ENCRYPTION_KEY` (يجب إبقاء `TELEGRAM_BOT_TOKEN` القديم مضبوطاً في أول تشغيل للترحيل، وأي سجل يتعذر فك تشفيره يُسجَّل كخطأ دون حذفه أو إيقاف التشغيل). **بعد إتمام الترحيل، يصبح التشفير مستقلاً تماماً عن `TELEGRAM_BOT_TOKEN` ولن يؤدي تدوير أو تغيير توكن البوت إلى كسر كلمات المرور المخزّنة.**
- **معرّف المالك (`OWNER_TELEGRAM_ID`):** إلزامي في متغيرات البيئة بلا قيمة افتراضية ويُتحقق منه عند الإقلاع.
- يحاول البوت حذف رسائل بيانات الدخول من تيليجرام فور استلامها لحماية خصوصية الطالب.

## ☁️ الاستضافة على Render Free + UptimeRobot وسياسة قاعدة البيانات

### 1. إبقاء الخدمة نشطة على Render Free (`UptimeRobot` + `/health`)
- يُنشر التطبيق كخدمة `type: web` على Render Free مع `healthCheckPath: /health` في `render.yaml` (تعيد نقطة `/health` حالة `200` عند سلامة قاعدة البيانات أو `503` عند تعذّر الاتصال).
- لأن خطة Render Free تدخل الحاوية في السبات بعد **15 دقيقة** من الخمول، أنشئ مراقباً مجانياً في **UptimeRobot** من نوع `HTTP(s)` يرسل طلباً كل **5 دقائق** إلى:
  ```text
  https://<your-service>.onrender.com/health
  ```
- تُحفظ أكواد الاقتران المؤقتة (`pair_codes`) وجلسات الأجهزة (`app_sessions` بمدة صلاحية افتراضية 30 يوماً) داخل قاعدة البيانات حتى لا تضيع عند إعادة تشغيل الحاوية.
- تأكد من ضبط جميع متغيرات البيئة المطلوبة في لوحة Render قبل النشر: `TELEGRAM_BOT_TOKEN`، `OWNER_TELEGRAM_ID`، `ENCRYPTION_KEY`، `WEBAPP_URL`، `DATABASE_URL`، و`DIRECT_URL`.

### 2. سياسة اتصال PostgreSQL (`DATABASE_URL` مقابل `DIRECT_URL` / PgBouncer)
- **التشغيل اليومي (Runtime Pool):** يفضّل النظام `DATABASE_URL` (منفذ PgBouncer Transaction Pooler مثل `:6543` مع `?pgbouncer=true`) عبر `psycopg_pool.ConnectionPool` مع تعطيل الـ Prepared Statements تلقائياً (`prepare_threshold=None`) عند اكتشاف PgBouncer لتجنّب استنزاف اتصالات Supabase المباشرة.
- **الترحيل وتهيئة الجداول (`init_db`):** عند توفر `DIRECT_URL` (المنفذ المباشر `:5432`) يستخدمه النظام لتشغيل عمليات DDL/الترحيل عند الإقلاع ثم يغلقه، وإلا يعود تلقائياً إلى `DATABASE_URL`.
- **SQLite محلياً:** عند عدم ضبط رابط PostgreSQL، يفعّل النظام تلقائياً `PRAGMA foreign_keys = ON` و`PRAGMA journal_mode = WAL` و`PRAGMA busy_timeout = 10000`.
